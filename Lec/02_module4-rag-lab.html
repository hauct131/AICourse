Module 04 · Lab

Xây RAG cơ bản → 2 process → API → UI (chat & upload)

Lab này bạn xây một RAG Basic hoàn chỉnh chạy local, rồi phơi ra 2 process: (1) indexing — nạp file từ input/ vào vector DB; (2) retrieval/chat — trả lời câu hỏi. Cả hai được bọc sau một API (/upload, /chat) để một UI đơn giản gọi: gõ chat và upload file để index. Đọc file lý thuyết 01_module4-rag-theory.html trước.

Quy tắc của lab này: KHÔNG chép sẵn code pipeline (Python) cho bạn. Lab cho cấu trúc thư mục + nhiệm vụ từng file + hợp đồng API — bạn tự viết logic (dùng Claude Code hỗ trợ). Các phần hạ tầng (Docker, entrypoint, SQL schema, migrations, UI) thì có sẵn để copy.

Hai process — trái tim của lab

📥
Process 1 — Indexing
Đọc .md từ input/ → cắt chunk (fixed-token) → embed (nomic) → lưu documents / chunks / embeddings. Chạy khi upload file hoặc nạp thủ công.
💬
Process 2 — Retrieval (chat)
Embed câu hỏi → tìm top-k chunk gần nhất → dựng prompt → gọi llama3.1 → trả lời + nguồn. Chạy mỗi lần người dùng hỏi.

Module 04 · Lab · Bước 2

Database — schema cho kho .md & migration tự áp dụng

Schema thiết kế cho kho rag-ai-local (QandA + functionality-docs) và tiến hoá qua nhiều lab: một schema, các cột cho lab sau đã có sẵn nhưng để trống tới khi cần. File đầy đủ: rag_pipeline/sql/init_rag_db.sql.

3 bảng

rag_documents
1 hàng / file .md. Có source_path, raw_content (Lab1) và các cột metadata/description/summary (Lab2, để trống lúc này).
rag_chunks
Nhiều hàng / document. content (chunk fixed-token) + chunk_index (Lab1); content_tsv full-text (Lab3).
rag_embeddings
1 vector / chunk. embedding vector(768) từ nomic. Tách riêng để đổi model embed mà không đụng chunk.
Chunk KHÔNG chỉ là "cắt token". Với file .md có frontmatter + TL;DR: ta tách metadata (title/date/area/status/tags), description, summary (TL;DR) ra cột riêng ở rag_documents; còn body thì cắt fixed-token thành rag_chunks. Lab 1 chỉ làm phần body (fixed-token) + embedding; Lab 2 mới parse metadata/summary; Lab 3 mới bật full-text/Elasticsearch.

init_rag_db.sql (trích — các bảng chính)

rag_pipeline/sql/init_rag_db.sqlidempotent
CREATE EXTENSION IF NOT EXISTS vector;

-- 1) DOCUMENTS — 1 hàng / file .md
CREATE TABLE IF NOT EXISTS rag_documents (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  source_path  TEXT NOT NULL UNIQUE,   -- vd rag-ai-local/QandA/07042026_....md
  raw_content  TEXT,                    -- [Lab1] toàn văn file
  -- [Lab2] điền từ frontmatter + TL;DR:
  doc_type VARCHAR(30), title TEXT, doc_date DATE, area VARCHAR(100),
  status VARCHAR(40), tags TEXT[], description TEXT, summary TEXT,
  metadata JSONB, created_at TIMESTAMP DEFAULT NOW()
);

-- 2) CHUNKS — nhiều chunk fixed-token / document
CREATE TABLE IF NOT EXISTS rag_chunks (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  document_id UUID REFERENCES rag_documents(id) ON DELETE CASCADE,
  chunk_index INT, content TEXT NOT NULL, token_count INT,  -- [Lab1]
  metadata JSONB,                    -- [Lab2]
  content_tsv tsvector,               -- [Lab3] full-text
  UNIQUE (document_id, chunk_index)
);

-- 3) EMBEDDINGS — 1 vector / chunk
CREATE TABLE IF NOT EXISTS rag_embeddings (
  id       UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  chunk_id UUID REFERENCES rag_chunks(id) ON DELETE CASCADE,
  embedding vector({{EMBEDDING_DIM}}) NOT NULL,  -- 768 = nomic
  model VARCHAR(80), UNIQUE (chunk_id)
);
-- + index, trigger updated_at, trigger content_tsv (Lab3). Xem file đầy đủ.

Migration tự áp dụng khi SQL đổi

migrations.py (đã cung cấp sẵn) áp dụng init_rag_db.sql lúc app khởi động. Điểm hay: nó lưu SHA-256 của file SQL — mỗi lần bạn SỬA schema, hash đổi → tự chạy lại (schema idempotent nên an toàn). Nó cũng thay {{EMBEDDING_DIM}} = 768.

Bạn không cần viết migrations.py — nó là hạ tầng có sẵn. main.py của bạn chỉ cần gọi run_migrations() trước khi start API.

Kiểm tra sau khi index

terminal
$ docker exec -it pgvector psql -U ai_user -d ai_db ai_db=# SELECT count(*) FROM rag_documents; → 2 ai_db=# SELECT count(*) FROM rag_chunks; → 12 ai_db=# SELECT count(*) FROM rag_embeddings; → 12 ✔ mỗi chunk 1 vector

async function send() {
  const r = await fetch("/chat", {
    method: "POST", headers: {"Content-Type": "application/json"},
    body: JSON.stringify({ question })
  });
  const data = await r.json();     // {answer, sources}
  add("RAG", data.answer, data.sources);
}

// Upload file -> POST /upload (multipart) -> index
async function upload() {
  const fd = new FormData(); fd.append("file", file);
  const r = await fetch("/upload", { method: "POST", body: fd });
  const data = await r.json();     // {chunks_indexed}
}
